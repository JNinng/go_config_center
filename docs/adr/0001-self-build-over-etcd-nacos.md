# 自建配置中心，而非采用 etcd / Nacos / Apollo

etcd 缺少业务所需的版本历史与回滚能力（MVCC revision 随压缩丢失），Nacos / Apollo 为 JVM 系统、启动慢且运维重，与"快速启动、轻量单二进制部署"的目标冲突。决定自研 Go 配置中心。Consul 定位服务发现而非配置管理，一并排除。

## Considered Options

- **etcd**：共识与存储成熟，但历史/回滚、灰度等业务层仍要自建，且引入 etcd 运维成本，等于两头做事。
- **Nacos / Apollo**：功能最全，但 JVM 启动慢、内存占用大，与部署目标冲突。
- **自建**：工作量最大，换取完全的业务形态控制与单二进制快速启动。
